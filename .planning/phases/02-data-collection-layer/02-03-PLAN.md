    3. At start of main(), initialize metrics and start session:
       ```typescript
       // Initialize metrics collector
       const metrics = MetricsCollectorService.getInstance()

       // Start session

       await metrics.startSession(sessionId)
       ```

    4. Add graceful shutdown handlers BEFORE existing logic:
       ```typescript
       const shutdown = async (signal: string, exitCode: number) => {
         console.log(`Received ${signal}, shutting down...`)

         // End analytics session
         await metrics.endSession(sessionId, exitCode === 0 ? 'user_exit' : 'error')

         // Shutdown metrics collector (flushes events)
         await metrics.shutdown()

         process.exit(exitCode)
       }

       process.on('SIGTERM', () => shutdown('SIGTERM', 0))
       process.on('SIGINT', () => shutdown('SIGINT', 0))

       process.on('uncaughtException', async (error) => {
         console.error('Uncaught exception:', error)
         await shutdown('uncaughtException', 1)
       })
       ```

    5. After CLI command completes, end session:
       ```typescript
       try {
         // ... existing CLI logic ...
         // ... command execution ...

         // Success - end session normally
         await metrics.endSession(sessionId, 'completion')
       } catch (error) {
         // Error - end session with error
         await metrics.endSession(sessionId, 'error')
         throw error
       } finally {
         // Always shutdown metrics
         await metrics.shutdown()
       }
       ```

    **Important:** Session tracking must not block CLI startup. All async calls should be non-blocking or fire-and-forget where appropriate.

    Reference: RESEARCH.md "CLI Integration Point" section

    - Session tracking doesn't block CLI execution
