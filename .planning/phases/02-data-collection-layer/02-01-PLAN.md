  <name>Task 4: Implement MetricsCollectorService with EventQueue integration</name>
  <files>cli/src/services/analytics/MetricsCollectorService.ts</files>
  <action>
    Create MetricsCollectorService extending EventEmitter with EventQueue integration:

    **Class structure:**
    - Singleton pattern (private static instance, getInstance())
    - Private constructor
    - Extends EventEmitter
    - Set maxListeners to 50

    **Properties:**
    - `storage: StorageService` - Get from StorageService.getInstance()
    - `queue: EventQueue` - Instantiate EventQueue with capacity 1000
    - `flushInterval: NodeJS.Timeout | null` - Periodic flush timer
    - `currentSessionId: string | null` - Track active session
    - `isShutdown: boolean` - Prevent events after shutdown
    - `privacyConfig: PrivacyConfig` - Use DEFAULT_PRIVACY_CONFIG

    **Constructor:**
    - Initialize storage service
    - Initialize queue: `this.queue = new EventQueue(1000)`
    - Setup periodic flush: `this.flushInterval = setInterval(() => this.flush(), 1000)`
    - Increase EventEmitter max listeners
    - Setup graceful shutdown handlers (SIGTERM, SIGINT, uncaughtException)
    - Log "MetricsCollectorService initialized"

    **Methods:**
    1. `getInstance(): MetricsCollectorService` - Singleton accessor
    2. `startSession(sessionId: string): Promise<void>` - Start new session via storage.startSession()
    3. `endSession(sessionId: string, exitReason: string): Promise<void>` - End session via storage.endSession()
    4. `emit<K extends keyof MetricsEvents>(event: K, data: MetricsEvents[K]): boolean` - Override emit to:
       - Check if shutdown (return false if yes)
       - Check if analytics enabled (return false if disabled)
       - Sanitize PII using PIISanitizer.sanitize()
       - Create MetricEvent with type, data, timestamp
       - Queue event via `this.queue.enqueue({ type: event, data: sanitized, timestamp: new Date() })`
       - Call super.emit(event, data)
    5. `private async flush(): Promise<void>` - Flush queued events to storage:
       ```typescript
       const batch = this.queue.dequeueBatch(100)
       if (batch.length === 0) return

       try {
         const eventsToInsert = batch.map(event => ({
           sessionId: this.currentSessionId || '',
           eventType: event.type,
           timestamp: event.timestamp,
           metadata: JSON.stringify(event.data)
         }))
         await this.storage.insertEvents(eventsToInsert)
       } catch (error) {
         console.error('Failed to flush metrics:', error)
         this.queue.requeue(batch)
       }
       ```
    6. `async shutdown(): Promise<void>` - Graceful shutdown:
       - Set isShutdown = true
       - Emit 'shutdown' event
       - Clear flush interval
       - Await flush() for final batch
       - Await storage.close()
       - Remove all listeners

    **Error handling:**
    - Attach 'error' listener to prevent crashes
    - Log errors but don't throw

    **Integration with StorageService:**
    - Import StorageService
    - Call storage.startSession/endSession/insertEvents (plural for batch)
    - Store sessionId for all events
    - Serialize event data to JSON for metadata column

    **Integration with EventQueue:**
    - Import EventQueue from './queue/EventQueue'
    - Use enqueue for immediate return (<5ms latency)
    - Use dequeueBatch in flush for batch insertion
    - Use requeue on failure to retry

    Reference: RESEARCH.md Pattern 1 and 2 (EventEmitter + EventQueue integration).
