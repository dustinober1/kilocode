    - Import `createHash` from 'crypto'
    - Create static class with methods:
      - `sanitize(data: Record<string, unknown>): Record<string, unknown>` - Recursively sanitize object
      - `sanitizeString(str: string): string` - Sanitize individual strings
      - `hashUsername(username: string): string` - SHA-256 hash to 16 hex chars

    Username patterns to hash (from RESEARCH.md):
    - `/users/([^/]+)` (Unix)
    - `/home/([^/]+)` (Linux)

    Prompt patterns to redact entirely:
    - `/password/i`
    - `/api[_-]?key/i`
    - `/token/i`

    **2. pathSanitizer.ts** - Path-specific sanitization:
    - Export `sanitizePath(path: string): string` function
    - Apply username hashing to filesystem paths
    - Preserve path structure (only hash usernames)
    - Handle both Unix and Windows paths

    Implementation details:
    - Use `createHash('sha256').update(username, 'utf8').digest('hex').substring(0, 16)`
    - Match patterns with RegExp and replace with hash
    - For prompt filtering, return "[REDACTED]" if any sensitive pattern matches
    - Handle nested objects recursively

    DO NOT create custom hash functions - use Node.js crypto module only.

    Create MetricsCollectorService extending EventEmitter:

    **Class structure:**
    - Singleton pattern (private static instance, getInstance())
    - Private constructor
    - Extends EventEmitter
    - Set maxListeners to 50

    **Properties:**
    - `storage: StorageService` - Get from StorageService.getInstance()
    - `currentSessionId: string | null` - Track active session
    - `isShutdown: boolean` - Prevent events after shutdown
    - `privacyConfig: PrivacyConfig` - Use DEFAULT_PRIVACY_CONFIG

    **Constructor:**
    - Initialize storage service
    - Increase EventEmitter max listeners
    - Setup graceful shutdown handlers (SIGTERM, SIGINT, uncaughtException)
    - Log "MetricsCollectorService initialized"

    **Methods:**
    1. `getInstance(): MetricsCollectorService` - Singleton accessor
    2. `startSession(sessionId: string): Promise<void>` - Start new session via storage.startSession()
    3. `endSession(sessionId: string, exitReason: string): Promise<void>` - End session via storage.endSession()
    4. `emit<K extends keyof MetricsEvents>(event: K, data: MetricsEvents[K]): boolean` - Override emit to:
       - Check if shutdown (return false if yes)
       - Check if analytics enabled (return false if disabled)
       - Sanitize PII using PIISanitizer.sanitize()
       - Create MetricEvent with type, data, timestamp
       - Queue event via `await storage.insertEvent({ sessionId, eventType: event, timestamp, metadata: JSON.stringify(data) })`
       - Call super.emit(event, data)
    5. `async shutdown(): Promise<void>` - Graceful shutdown:
       - Set isShutdown = true
       - Emit 'shutdown' event
       - Await storage.close() to flush events
       - Remove all listeners

    **Error handling:**
    - Attach 'error' listener to prevent crashes
    - Log errors but don't throw

    **Integration with StorageService:**
    - Import StorageService
    - Call storage.startSession/endSession/insertEvent
    - Store sessionId for all events
    - Serialize event data to JSON for metadata column

    DO NOT implement event queue in this service - StorageService already has batching queue. Just call insertEvent().

    Reference: RESEARCH.md Pattern 1, but simplified (no separate EventQueue since StorageService has it).
